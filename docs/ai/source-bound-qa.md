# 指定来源问答与 h007 复查

## 结论修正

2026-11-08 复查发现，旧 `holdout_v1` 的 h005–h008 绑定了种子 SQL 的文章16
《一次 23 秒的请求：Redis 超时是怎么把接口挂住的》，但本机公开库的同号文章实际是
《微服务验证之星》，正文仅用于验证微服务链路。指定的排障文章没有进入当前公开语料。

当前语料与旧三轮报告的指纹均为
`2ee1deed87fdcc3a09f1daf62267492c5036e7973606704693e17300b7b63fcd`。
这说明旧评测执行时就存在标注与来源不符，不能解释为后来删文造成。
旧 h007 三轮都只返回笔记13、12、11的摘录，没有文章16；笔记13虽有60000与5000两个数值，
也不能证明指定排障文章写了这些内容。

因此撤回旧报告的“46/48正确、两次误拒”语义结论。原始答案、复核及统计文件全部保留，
但不再作为有效验收成绩；不能把前一轮借用笔记回答认定为指定文章回答正确。

## 修复范围

评测题集新增同名的 `*.sources.json` 清单，将题号绑定到来源类型、ID、完整标题、
原文证据及可选的版本。`holdout_v2/v3` 同时固定原文版本；缺失来源的负例也检查标题仍未公开。
留出集缺清单、ID复用、标题不符、版本变化、证据缺失都会在调用模型前报错。
旧非留出集无清单时兼容原行为，不宣称已校验来源。

完整问答评测台在开始、续跑、模型复核前校验；检索评测、网关问答验收脚本与混合阈值标定也复用此检查。
CLI原始报告保存题集、清单、语料指纹与当轮校验范围；离线汇总检查这些证据，拒绝给旧的无来源证明报告续用分数。
清单是本地验收追溯信息，不是密码学签名。仅检查引用文本存在仍不能代替语义复核。

`holdout_v2` 首轮暴露真实缺陷：明确要求“只根据《完整标题》”时，仍从另一篇笔记回答Druid数值。
v2参与诊断后转为回归集；原题及执行结果保持不变。
问答现对“只/仅根据/依据《完整标题》”识别明确来源限制，普通问答与SSE共用处理：

- 先按现有公开状态复核查找完整标题；来源不存在时直接返回 `doneReason=refused`，无引用、无模型调用。
- 来源存在时，只把对应类型及ID的召回片段交给生成模型；没有该来源片段则拒答。
- 保留撤回保护，不把历史对话或记忆当证据。

这项处理只覆盖明确完整标题写法，不做模糊文章名推断，也不保证指定来源能进入全站召回候选。
普通问答的阈值、模型、提示词未改。仅标题相同的不同文章无法通过自然语言标题进一步区分。
Python镜像须包含运行时题集及来源清单；`.dockerignore` 只放行 `tests/fixtures/eval/*.json`，其余测试代码仍排除。
