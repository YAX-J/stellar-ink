# 首页 Lighthouse 分析与性能改进

## 用户报告

输入：`127.0.0.1_4173-20261110T194801.json`，Lighthouse13.5.0，移动端模拟节流。
性能54、无障碍98、最佳实践100、SEO100；FCP1.38s、LCP4.87s、TBT1993ms、CLS0。

证据：

- 样式与布局约4993ms，主线程总工作7146ms；脚本执行约676ms。
- 39个字体请求，字体传输约2.22MB；中文字体CSS传输约186KB、解压后约678KB。
- 强制重排条目约448ms；首页小星图每帧调用 `fitCanvas`，读 clientWidth/clientHeight。
- 本机接口请求响应较快，没有证据支持把本轮问题归因于数据库慢查询。
- 无障碍扣分指向 `PostCard`：h2之后跳到h4。

报告证据能确定资源和主线程开销，不能仅凭压缩包中的函数偏移，把全部耗时都归因到某一个组件。

## 改动

1. 中文字体请求由六个离散字重变为两个变量区间：Sans300..700、Serif600..900。
   以同一 Chrome User-Agent 获取Google官方CSS，字体URL集合完全一致（202个）；@font-face从606条降为202条，
   CSS gzip约186516→62198字节。保留`.cn`、非阻塞加载、swap和原有字体栈，没有添加字体资产或运行时依赖。
2. 首页背景与小星图使用共享 `useCanvasAnimation`：在ResizeObserver回调中按2倍尺寸适配位图，帧内不读取布局。
   动画上限30fps，隐藏页面、离屏时停帧，减少动效时只画静态帧；数据、尺寸和主题改变仍可更新。
   背景明确CSS尺寸，避免HiDPI位图引发固有尺寸递增；星图点位按业务变化缓存。颜色采用主题变量。
3. 文章卡片h4改h3，保留原字号／字重样式，修复标题层级。

字体区间请求依据：[Google Fonts CSS2](https://developers.google.com/fonts/docs/css2)；布局读取原则见
[避免强制同步布局](https://web.dev/articles/avoid-large-complex-layouts-and-layout-thrashing)。
