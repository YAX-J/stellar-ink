## 真正修复的问题

`QaService` 原来把每个已召回子块再次截为前 200 字，并把追加的「…」作为片段的一部分交给模型。
检索评测只验证文章命中，因此显示 12/12 可答题都命中；答案句却可能在模型看到之前被删掉。
原文一致性核验也会因「…」不在原文中而失败。

本轮问答默认片段长度与标准子块长度对齐（320 字），保留块尾证据。
当前公开子块原始正文最长 316 字，可以完整送入。
仍受 8 条引用、4000 字总上下文预算约束；Agent 的 200 字预览长度未改。
显式裁短的片段保持原文子串，不追加展示字符；严格原文核验规则未放宽。
最终四道失败题都已确认答案在原始召回块内，无需改召回或增加相邻块扩展。

同时收紧拒答说明：约定首句后只指出缺少什么事实，避免将一条线索泛化成全部摘录。
没有增加事实核验服务或额外生成步骤。

## 如何复跑与查看证据

### 在评测台运行

站长打开 `/ai-lab?tab=eval&mode=qa`，选择「完整问答验收」，默认使用独立验收集24题。
可先跑3题或执行全部；页面展示逐题进度、真实答案、依据充分标记、原文摘录与打开原文的链接。
「停止后续题目」会让当前题完成后停止，再点「继续剩余题目」从下一题接着跑。
失败单独展示并保留 traceId，不计作拒答；预算用尽也单独展示。
引用按文档归并：同一笔记或文章只显示一张来源卡，展开可查看每个片段的原文和原始编号。
问答面板与助手浮层同样按文档归并；同号文章/笔记仍分别显示，引用检查继续逐片段统计。

自动检查只统计引用片段能否回查、编号有无越界以及是否漏标编号。
两项人工指标初始均为「待复核」：逐题选择答案是否正确完整、正文引用是否支持实质结论，
以已复核的题目为分母统计，并同时显示复核数量。纯拒答和预算未完整结束的回答不进入事实引用支持率。
复核提交绑定该题答案哈希，服务端维护结果，客户端不能提交自动分数。
切换账号清除前一个账号的界面状态，旧异步请求不会把其结果重新写回来。

### 命令行收集与离线复核

```powershell
cd stellar-ink-ai
$env:MYSQL_HOST='127.0.0.1'
# 使用本机有问答权限的账号；凭据只保留在本次进程环境中。
$env:QA_EVAL_USERNAME='<验收账号>'
$env:QA_EVAL_PASSWORD='<验收密码>'
uv run python scripts/eval_qa_answers.py --output data/qa-answers-final.json
```

脚本经网关登录，每题保存完整问题、参考答案、实际响应、引用核验、耗时。
没有逐题语义复核时，`answerAccuracy` 和 `citationSupportRateByAnswer` 为 null，
退出码0只表示调用完成且无HTTP/业务错误，不代表语义验收通过。
凭据和登录 token 不进入结果文件。

逐题核对后，用匹配本轮响应哈希的复核文件离线汇总：

```powershell
uv run python scripts/eval_qa_answers.py --input data/qa-answers-final.json `
  --review data/qa-answers-final-review.json --output data/qa-answers-final-reviewed.json
```

本轮产物均位于忽略的 `stellar-ink-ai/data/`：

- `qa-answers-baseline.json` / `qa-answers-final.json`：真实完整响应。
- `qa-answers-baseline-review.json` / `qa-answers-final-review.json`：逐题结论与答案哈希。
- `qa-answers-baseline-reviewed.json` / `qa-answers-final-reviewed.json`：汇总和核对结果。
- `qa-final-sse-acceptance.json`：四道曾失败的可答题与两类拒答题的真实网关SSE事件、引用核验。

SSE 的导航、curl、咖啡/慢走、植物段落问题全部正常回答；同主题缺事实与跨主题问题均正确拒答。
