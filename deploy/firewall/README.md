# 源站防火墙规则（UCloud 安全组 + 主机层）

## 先说清楚：UCloud 公共云的安全组没有「文件导入」

我查了官方文档：UCloud 公共云的安全组规则是**逐条编辑**的（弹框里填「策略 / 协议类型 / 来源 IP / 端口 / 优先级」），
不像某些云有「导入规则」的模板文件。「导入/导出安全组规则」那种页面属于青云 QingCloud 与基于 UCloudStack 的私有云，
不是 UCloud 公共云控制台。

所以这个目录给的是**最接近「可直接使用」的两种形态**：

| 文件 / 脚本 | 用途 | 导入方式 |
|---|---|---|
| `ucloud-security-group.csv` | 安全组规则的逐条清单（Excel 可直接打开） | 打开后**一行一行照着填**控制台弹框；也可作为规则的唯一来源长期维护 |
| `../scripts/firewall.sh` | **主机层真·一行导入** | 服务器上 `sudo bash deploy/scripts/firewall.sh`，自动读 `deploy/docker/nginx/cloudflare_real_ip.inc` 的 CF 网段并写入 ufw + DOCKER-USER |

## CSV 里有什么

共 46 条（+1 行表头）：

- **1 条**：`22` ← 你的固定公网 IP（记得把占位符改掉）；
- **22 条**：`443` ← Cloudflare 全部网段（15×IPv4 + 7×IPv6）；
- **22 条**：`80` ← 同上，**可选**（只有 CF 走 80 才需要；容器健康检查走内部回环）；
- **1 条**：`ICMP` ← `0.0.0.0/0`，保留路径 MTU 发现；
- 其余入站端口不加即为拒绝。**3306 / 6379 / 6333 / 8848 一条都不要加**（它们只绑 127.0.0.1）。

UCloud 的「优先级」数值越小越优先，这里全填 `100`（互不重叠，随便填都行）。

## 省事路径（不想在控制台加 22 条时）

1. 安全组先只加两条：`22 ← 你的 IP`、`443 ← 0.0.0.0/0`；
2. **立刻**在服务器上跑 `sudo bash deploy/scripts/firewall.sh`——主机层会把 80/443 收紧到 CF 网段
   （写的是 `DOCKER-USER` 链，Docker 绕不过去，实测有效）；
3. 有空再把安全组的 443 收窄成 CSV 里那 22 条（网络层 + 主机层双保险）。

> ⚠️ 第 2 步之前不要停：只做第 1 步等于源站 443 对全网开放（虽然 nginx 只认 CF 回源的 Host/证书，
> 但端口暴露本身就会招扫描）。

## 想真正批量刷安全组？

只有 API/CLI 这条路（`UpdateFirewall` 支持一次覆盖全部规则）。需要：
1. 你账号的 API 公钥/私钥（控制台 → API 密钥）；
2. 核对参数名（`Rule.N.Protocol` / `Rule.N.Port` / `Rule.N.SrcIP` / `Rule.N.Action` / `Rule.N.Priority` 之类）。

官方 API 文档页面是前端渲染的，我抓不到参数表。你要是想走这条路，把控制台里那页 API 文档的参数部分截图发我，
或者跑一次 `ucloud firewall update --help` 把输出贴给我，我按真实参数名写一个批量脚本。
